# Hoomy 会话化重构规格

状态：ready-for-agent　日期：2026-09-14

术语以 `CONTEXT.md` 为准（新增「会话」「登录闸口」）；技术决策见 `docs/adr/0015-session-as-sole-data-entry.md`；产出本规格的架构走查与盘问记录见下方「补充说明」。

## 问题陈述

从用户的视角，有三件事今天做不到或做不到位：

- **切走再切回来，看到的是旧数据。** 五个 Tab 页面同时挂载在一个保留状态的容器里，每个页面只在**第一次挂载时**取一次数，全项目没有任何刷新入口。于是在手机上收藏的歌，电视上切到「我喜欢的歌曲」看不到；列表里那首歌的星标也还是旧的。
- **页面可能在没有任何解释的情况下整片空白。** 十个页面各自有一条「没有数据源就画空白」的分支。它今天是死分支，但它表达的是一个真实状态（凭据读不出来、会话已消失）—— 真发生时，用户看到的不是登录页也不是错误提示，而是空白。
- **退出登录是否回到登录页，取决于调用点有没有记得清路由栈。** 今天只有设置页记得（且带注释说明为什么），其它入口不记得。

从维护者的视角，根因是一个：**「当前有没有会话」这件事没有归宿，被复制了十四份**（七个数据提供者各自判空、十个页面各写一遍空白守卫、播放层再判三次、登出处还要记得弹栈）。它带来的直接后果是：

- 那个守卫是死分支，却让**十一处页面测试必须假装未登录**才能渲染；
- 播放引擎被一句与它无关的判断当成「已登录」开关，引擎本身根本不需要会话；
- 「未登录」被塞进了协议的异常码空间，与网络错误共用同一个码；
- 页面的取数身份、失效、数据位置三件事没有归属，「全库已取回」这条不变量无处声明 —— 将来真改成增量加载时，本地搜索会静默返回不完整结果。

## 解决方案

把「当前已登录的服务器会话」做成一个模块，成为取数的唯一入口：

- **会话**是被登录闸口注入的非空模块，提供数据取数、收藏写、歌词，以及两个媒体地址（歌曲播放地址、封面地址）。协议客户端本体不外露，协议词汇不再漏进页面与播放层。
- **登录闸口是唯一表达「没有会话」的地方**：有会话就进主界面，没有就是登录页。主界面之内不再有第二种形态。
- **取数以异步值的形式出现在接口上**，页面只订阅它；载入／错误重试／空态的呈现收敛到一处。
- **传输只有一条**：登录校验、协议客户端、封面下载共用同一条 HTTP 传输，于是它也是唯一的测试替身注入点。
- **会话消失是路由事件**：登出或凭据失效由路由重置导航栈回登录页。

用户能感知到的变化是：页面不再无声空白；退出登录一定回到登录页；数据在明确的时机刷新（见下一条）；其余行为不变（浏览、播放、歌词、收藏、队列持久化的规则一条都不动）。

## 用户故事

1. 作为用户，我想切走再切回一个 Tab 时看到最新的曲库与收藏状态，以便不必重启 App 才能看到别处改过的内容。
2. 作为用户，我想在电视上看到手机上刚收藏的那首歌已经带星标，以便确认收藏是跨设备同步的。
3. 作为用户，我想退出登录后一定回到登录页，以便把设备交出去时不会停在某个详情页上面看不见登录入口。
4. 作为用户，我想在任何页面都不会看到「没有数据源」造成的整片空白，以便遇到问题时至少得到解释或重试机会。
5. 作为用户，我想在任何页面点歌都能播放，以便不会遇到「点了没反应」这种静默失效。
6. 作为用户，我想「全部播放」与「随机播放」永远可用，以便不会因为登录相关的判断而静默失效。
7. 作为用户，我想登录一次之后重开 App 直接进曲库（既有行为不回归），以便随手打开就能听。
8. 作为用户，我想收藏失败时仍有明确提示与回滚（既有行为不回归），以便不必猜是不是没点上。
9. 作为用户，我想播放队列与播放位置在重启后仍然恢复（既有行为不回归），以便接着上次的听。
10. 作为用户，我想 Android TV 上的遥控器操作与焦点反馈完全不受影响，以便这次改动不让电视变难用。
11. 作为维护者，我想「有没有会话」只在一个地方判断，以便不必在十四个位置同步维护同一条不变量。
12. 作为维护者，我想新增一个浏览页面时只声明「我要什么数据」，以便不必再写一遍取数、空态与判空。
13. 作为维护者，我想页面测试不必假装未登录，以便用例只表达它真正要验证的事。
14. 作为维护者，我想测试默认只替换传输这一道接缝，以便不为渲染类用例再造一个假模块。
15. 作为维护者，我想「全库已取回」这条不变量有地方声明与验证，以便将来改增量加载时知道要动哪里。
16. 作为维护者，我想协议词汇不出现在页面与播放层，以便播放层只理解领域词汇。
17. 作为维护者，我想传输策略（超时、重试、TLS、代理）只写一遍，以便不会漏改其中一条。
18. 作为维护者，我想播放层只依赖两个纯函数（两个地址），以便引擎与会话彻底解耦。
19. 作为维护者，我想登出是一个动作而不是「记得弹栈」，以便新增登出入口时不会漏。
20. 作为维护者，我想载入／失败重试／空态只有一处呈现，以便文案与交互口径一致。
21. 作为维护者，我想「未登录」不再占用协议的异常码，以便网络错误与登录错误可区分。
22. 作为维护者，我想页面数据的失效有一个明确的落点，以便刷新时机是一条可测的行为而不是散落的偶然。

## 实现决策

**模块与接口**

- 新增**会话**模块：以登录闸口注入的非空形式存在。它提供：全库歌曲、全库专辑、专辑曲目、全库歌手、歌手详情、歌单列表、歌单曲目、风格列表、风格曲目、我喜欢的歌曲、歌词、收藏写操作，以及两个媒体地址函数。**不暴露协议客户端本体。**
- 会话内部承担原本散在三处的「全库取数」：分页页大小、翻页循环、去重与防死循环、解析容错。原按实体切分的取数层里，有真深度的成员（歌手详情、歌词缓存）成为会话的内部实现；纯转发的成员随之消失。
- **取数以异步值形态出现在接口上**（每个取数操作对应一个可按参数区分的异步值），页面订阅它而不是自己持有取数回调。呈现层只把异步值画成载入／错误重试／空态。
- **登录闸口**在挂主界面时注入会话（嵌套作用域），因此主界面之内会话在类型上不可能为空。**约束：同一份凭据下会话实例必须稳定**，否则下游会重算并反复取数。
- **传输归一**：登录校验、协议客户端、封面下载共用同一条传输。封面组件里走框架自带 HTTP 栈的那条路径不并入。
- **登出/凭据失效**：路由订阅会话状态，重置导航栈回登录页。
- **播放层**：两个地址函数来自会话；引擎与会话无关（删掉那句把它当「已登录」开关的冗余判断）。
- 外壳保留一层统一兜底（复用既有错误重试呈现），仅在不变量被破坏时可能出现。

**明确不做**

- 不改取数策略本身：仍是一次取全库（ADR-0005 不变），仍不显示总数或页码。
- 不改队列口径、队列持久化格式与随机/循环规则（ADR-0012 不变）。
- 不放宽安全要求：凭据仍只进安全存储，传输仍只支持标准证书校验。
- 不引入下拉刷新，也不引入应用前台恢复时的重取。

**失效**（独立票据）

- 切回一个 Tab 时，使该 Tab 的取数失效并重取。局域网内代价约两个请求，换来「跨设备同步可见」。

## 测试决策

**好测试的标准**：只测外部行为，不测实现细节。断言「给定这组服务端响应 / 这个会话状态，得到这个领域结果或这个界面」，而不是「调用了哪个方法」。测试不应因内部重构而失败。

**接缝（沿用最高、最少的原则）**

- **传输**是既有接缝，也是本次唯一的功能接缝：生产一条真实传输，测试一条假传输。会话及其取数逻辑都是真的，测试只替换传输。
- **会话注入点**是登录闸口的作用域入口：渲染类用例（视觉、布局、TV 焦点）用它注入一个「真会话 + 假传输」；只有当用例意图与取数本身无关、或需要构造特定异步状态（加载中／失败／空）时，才替换具体的取数异步值。
- 不为会话造第二个假实现：那会引入一个新接缝，而现在的两个适配器（生产传输、假传输）已经足够。

**要覆盖的**

- 会话的取数操作：跨假传输验证分页、解析、容错与「全库取回」的完整性（既有 `subsonic_client_test` / 各取数层测试是直接先例，可平移）。
- 登录闸口：未登录显示登录页、已登录进主界面、登出后回到登录页且**已压入的层级路由被清掉**（先例：既有的根路由用例、设置页登出用例）。
- 页面：不再有「无数据源」空白分支；载入／失败重试／空态三态由统一呈现承担（先例：既有页面测试，跨假传输）。
- 播放层：两个地址函数来自会话；引擎不依赖会话（先例：既有播放控制器测试，用假引擎）。
- 失效：切回 Tab 触发重取（先例：既有收藏乐观更新用例的观察方式）。

**真机验收（不可自动化）**：iOS 与 Android TV 上各走一遍「登录 → 浏览 → 播放 → 收藏 → 切 Tab 看同步 → 退出登录回到登录页」；TV 上额外确认遥控器焦点与媒体键不受影响。

## 范围之外

- 播放队列的两种口径（走查候选 3）与歌曲行的三份实现（走查候选 2）—— 各自独立。
- 走查候选 5 的完整形态（按深度重划取数层）在本规格中只做到「会话吃掉纯转发成员」这一步。
- 走查候选 6（字母跳转的几何契约）、候选 7（领域模型同时是协议模型与落盘格式）、候选 8（高亮到铺蓝的视觉）。
- 封面组件走框架自带 HTTP 栈的那条取图路径。
- 下拉刷新、应用前台恢复时的重取。
- 播放引擎疑似缺少释放（`PlayerEngine.dispose` 全仓库无调用、provider 无释放钩子）—— 待运行期验证，另开票据。
- 登录闸口之外任何形式的「离线浏览」（MVP 不做离线）。
- TV 上专辑／艺术家列表缺少快速定位（票据 16 记录的既有缺口）。

## 补充说明

- **产出本规格的走查**：两条独立的架构走查（浏览/呈现层、数据/播放层）于 2026-09-14 完成，报告与证据见会话记录；九条加深机会中，本规格只做第一条（「已登录会话」没有归宿），其余八条保持独立。
- **盘问中明确纠正过一处**：走查报告最初把播放层写成「四个消费点各自推导」，核实后实为两个真实依赖（两个地址函数）加一个纯冗余门闩。本规格按后者执行。
- **既有决策的关系**：ADR-0014 已把「凭据读不出来」定义为「未登录」，本规格把「未登录只在闸口表示」补上；ADR-0005 与 ADR-0012 不做修改，只是取数这件事第一次有了承接增量加载改动的接缝。
- **票据切片**：① 会话根与传输归一（行为不变）② 闸口注入与页面取数切换 ③ 播放层解耦 ④ 切回 Tab 时失效。①②③ 按依赖顺序，④ 可后置或跳过。
