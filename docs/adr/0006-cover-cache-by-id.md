# 0006 - 封面按 coverArt id 缓存，不设 TTL，不做条件请求

日期：2026-09-10　状态：已接受

## 背景

需求要求封面磁盘缓存并提供清除缓存入口。可选的失效策略：TTL 自动过期、HTTP 条件请求（ETag/Last-Modified）、或按资源 id 永久缓存。

## 决策

按 `coverArt` id 缓存到磁盘，**不设过期时间**，失效仅靠设置页的手动「清除缓存」。

1. 不做 TTL：Navidrome 的 `coverArt` id 由歌曲/文件内容派生（实测形如 `mf-<songId>_<hash>`），元数据变化会生成新的 id，因此「id 不变即内容不变」成立，TTL 只会带来无收益的复杂度与重复下载。
2. 不做条件请求：Subsonic 的 `getCoverArt` 没有标准的 ETag/Last-Modified 支持，且认证参数每次携带新 salt，无法套用 HTTP 缓存语义。

## 后果

- 缓存只增不减，长期使用后占用可控但需用户主动清理（已由设置入口覆盖）。
- 若服务端更换了封面但 `coverArt` id 未变（理论上不应发生），客户端会一直显示旧图，需清缓存才能更新。
