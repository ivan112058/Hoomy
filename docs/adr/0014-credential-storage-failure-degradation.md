# 0014 - 凭据存储失败时降级：读失败按未登录，写失败不拦登录

日期：2026-09-14　状态：已接受

## 背景

票据 06 曾记下一条结论：「`flutter_secure_storage` 在这台 Sony 电视上不可用，登录态无法持久化（用户故事 5 在 TV 上失效）」。票据 17 复验时**未能复现**：全新安装 3/3 轮都写入成功并能跨冷启动读回，真实 App 上 09-11 写入的凭据至今有效（取证见票据 17）。当时在 `logcat` 里看到的 `W KeyStore: KeyStore exception` 是**别名尚不存在时取证书的框架噪声**（`ServiceSpecificException code 7`，框架吞掉后返回 null），随后插件正常生成密钥 —— 它不代表读写失败。

不过这次复验查出了两条会**放大**这类故障的真实缺陷：

1. **读失败会中断启动。** `CredentialStore.read()` 抛异常 → `AuthController.build()` 抛 → 根路由渲染整页「读取登录状态失败」，没有登录入口也没有重试，应用就此没有出路。
2. **写失败会拦住登录，且登录页看不见任何登录错误。** `AuthController.login()` 用 `AsyncValue.guard` 把包括「凭据写不进去」在内的所有错误写进 `authProvider` 的错误态；于是密码正确也进不去，而登录页那两个 `catch` 永远不会执行（`login()` 从不抛）。副作用是：**密码输错也会跳到整页「读取登录状态失败」**。

## 决策

1. **读失败 = 未登录。** `CredentialStore.read()` 把安全存储异常与不可解析的内容都收敛成 `null`。启动路径永不因凭据读取失败而中断。
2. **写失败 ≠ 登录失败。** 凭据校验（`ping`）通过即进入已登录态；落盘失败只把 `credentialsPersisted` 置 false。
3. **失败必须可见。** `credentialsPersisted == false` 时登录页用中性 SnackBar 告知「凭据未能保存到本机，下次打开需要重新登录」。这与 ADR-0012 队列持久化的「静默放弃」不同：队列丢了用户当场看得出来，凭据悄悄丢会让用户以为已经登着。
4. **`login()` 只在成功时改全局状态，并把失败抛给登录页。** 一次登录尝试的失败（密码错、连不上、存不下）是登录页要呈现的错误，不再进入 `authProvider` 的错误态。根路由的 AsyncError 分支从此只是兜底。
5. **不放宽安全要求。** 凭据仍然只进 `flutter_secure_storage`；失败时的降级是「这一次不落盘」，不是「换个地方明文存」。

## 后果

- keystore 坏掉的设备上应用仍然可用：能登录、能听歌，代价是每次打开要重登一次，并且用户知道原因。
- 登录页的 `SubsonicException` / `FormatException` 分支从死代码变成唯一路径；「用户名或密码错误」这类提示第一次真正显示在登录页上。
- 退出登录仍要求清除成功：那是用户交回设备前的安全动作，失败就该报出来，不走本 ADR 的降级（沿用 `CredentialStore.clear()` 的抛异常语义）。
- 真机上无法制造 keystore 失败，因此降级路径由平台替身注入失败来覆盖（`test/credential_resilience_test.dart`），真机只验「正常路径不回归」。
