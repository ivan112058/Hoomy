# 0009 - 用 lpinyin 做拼音首字母分组，不足处自行兜底

日期：2026-09-10　状态：已接受

## 背景

歌曲、专辑、歌手需要按拼音首字母分到 A–Z / # 组，供列表分组与 A-Z 快捷栏使用。参考项目用 Android 的 ICU `Han-Latin` 转写，但那是平台 API（且仅 Android API ≥ 29 可用），Flutter 侧没有等价能力：`intl` 不能转写，Dart 标准库无转写，Flutter 引擎虽带 `icudtl.dat` 但未对 Dart 暴露。iOS 也有平台转写 API，但没有任何现成 Flutter 插件封装，两平台各写一套成本明显更高。

包的选择：`lpinyin` 2.0.3（2021-05-11）纯 Dart、零依赖、源码 416 KB，实测在 Dart 3.13.2 可运行，但**实质停更**；`pinyin` 3.3.0（2024-04-16）是其后继且仍维护，但源码 4.08 MB，为「取首字母」这一个用途大 10 倍。

## 决策

用 **`lpinyin`**，并在它之上自己兜底三处不足：

1. **分组键须自行计算**。`getShortPinyin('五条人')` 返回的是全拼首字母串 `"wtr"`，不是 `"W"`。取组键的正确方式是 `getFirstWordPinyin(name).substring(0, 1).toUpperCase()`（`getFirstWordPinyin('五条人')` = `wu`）。
2. **非中文输入须归一化**。非中文原样返回且**保留空格**（`"The Beatles"` → `The Beatles`，`"  空格 首"` → `"  kg s"`）。必须先 `trim()`，再判断首字符是否落在 A–Z，否则会漏进 `#` 组。
3. **多音字姓氏自行修正**。两个拼音包都**不做姓氏读音**，且各有各的错：`单田芳` → D（应 S）、`区瑞强` → Q（应 O）、`曾`/`尉迟`/`仇`/`查`/`解` 等在两包间结论互相矛盾。策略是维护一份**简短的姓氏修正表**，只覆盖「已发现的错组」，不追求完整姓氏库。

不采用平台 ICU 转写（各平台各一套实现），不采用 `pinyin`（体积不划算）。

## 后果

- 依赖一个 2021 年后停更的包。风险可控：它纯 Dart、零依赖、无原生代码，停更的表现是词典不再扩充，而非「不再可用」；真要替换，接口面只有「取首字母」一处。
- 姓氏误读是**已知且未完全消除**的缺陷：生僻姓氏仍可能落错字母组。这影响的是 A-Z 快捷栏的跳转位置，不影响列表内容正确性，属可接受缺陷。切片 12 实施时需先跑一遍曲库、把实际错组补进修正表。
- 若将来要更准确的中文排序，正确方向是引入完整拼音词典并做分词，而不是换包。
