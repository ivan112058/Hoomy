# 0003 - 视觉与交互语言对齐 SmartisanMusic-Revived，但只取视觉层

日期：2026-09-10　状态：已接受

## 背景

Hoomy 的视觉与交互以 `SmartisanMusic-Revived`（锤子音乐 8.1.0 的 Android 复刻，Kotlin + Compose，commit `428ac08`）为基准。但两者形态根本不同：参考项目是 **Android 原生 + 纯本地**（Manifest 无 `INTERNET`，MediaStore 扫本地文件，Media3 播放，歌词只解析音频文件内嵌标签），Hoomy 是 **Flutter 跨四平台 + 串流**（数据全部经 Subsonic API 取自 Navidrome，客户端拿不到音频文件）。

## 决策

只移植**视觉与交互层**，不移植实现机制：

1. **照搬**：配色 token（浅色页底 `#ffffff`、深色 `#25282d`/`#34373c`、主文字 `#cc000000`、次文字 `#66000000`、分隔线 `#ebebeb`/`#3a3d42`、播放态红 `#e64040`、交互与歌词蓝 `#4a69b3`/`#5c89f2`）、字号层级（标题栏 20sp、列表标题 16sp、副标题 13sp）、间距（列表行 60dp、标题栏 50dp、分隔线 0.67dp 整宽）、直角方块化布局、固定 3 列专辑网格、字母快捷栏、层级页面与全屏覆盖层的动效语法。
2. **不照搬**：位图 selector 驱动的按压反馈（Flutter 无对应机制，改为「蓝底 + 文字变白」的等效反馈）、NinePatch 资源、Media3 媒体会话、内嵌标签解析。
3. **不实现**：黑胶唱盘旋转、唱针拖拽 seek、搓碟、爆豆音。原因是这些依赖 `media_kit` 不暴露的能力——搓碟需读取解码后的 PCM 窗口实时输出，Flutter 侧无对应 API。播放页为静止封面。
4. **新增**：底部 Tab 之上的常驻迷你播放条（参考项目有，`CONTEXT.md` 此前未定义）。

## 后果

- 观感目标可达，且不引入平台特有风险；代价是放弃参考项目最具辨识度的黑胶交互。
- 若将来要恢复唱盘旋转（纯动画，不含搓碟），成本可控：旋转只是 `AnimationController` 驱动的 `rotationZ`。
- 参考项目的深色模式本就是其自创设计（原版锤子音乐 8.1.0 无深色），我们同样沿用这套炭灰色板。
