# 0015 - 会话是取数的唯一入口，闸口之外不存在「无会话」形态

日期：2026-09-14　状态：已接受

## 背景

2026-09-14 的架构走查（浏览/呈现层与数据/播放层各一次）得出同一个根因：**跨模块的概念没有归宿**。其中一处是「当前有没有会话」：

- 七个 repository provider 各自 `client == null ? null : X(client)`；
- 十个页面各写一遍 `if (repository == null) return const SizedBox.shrink()`，而这是**死分支** —— 根路由只在已登录时挂外壳；
- 播放层再判三次，其中 `playerEngineProvider` 那次纯粹是「已登录」门闩（引擎构造根本不需要会话），且与 `playerControllerProvider` 重复；
- 登出处还要靠调用点记得 `Navigator.popUntil`，否则停在设置页；
- 十一处页面测试为了渲染必须假装未登录（`overrideWithValue(null)`）；
- `StarStore` 甚至把「未登录」造进了协议的异常码空间（`SubsonicException(-1, …)`，与网络错误的 `-1` 冲突）。

另一条独立观察同源：页面的**取数身份、失效、数据位置**没有归属。`AsyncView` 承诺「异步取数归我」，实际一件也没接住；页面活在 `IndexedStack` 里且它的 future 在 `initState` 定住，全项目没有下拉刷新 —— 于是跨设备同步来的收藏状态永远到不了已挂载的页面。

需求侧与既有决策都已确认「无会话」是一个独立、必须可见的状态（spec 用户故事 5／52；ADR-0014 把「凭据读不出来」定义为「未登录」）。

## 决策

1. **会话是取数的唯一入口。** 当前会话提供数据取数、收藏写、歌词与两个媒体地址（歌曲播放地址、封面地址）。协议客户端本体不外露，因此协议词汇不再漏进页面与播放层。
2. **闸口是唯一表达「无会话」的地方。** 登录闸口在挂主界面时注入会话，主界面之内会话在类型上不可能为空；页面不写「没有数据源时画什么」。外壳保留一层统一兜底（复用既有错误重试呈现），但它只在不变量破了时才可能出现。
3. **会话消失是路由事件。** 登出或凭据失效由路由订阅会话状态处理，重置导航栈回登录页，不再依赖调用点记得弹栈。
4. **取数操作以 provider 形态出现在接口上**，而不是会话对象上的方法。于是取数身份、缓存与失效落在模块内部，页面只订阅一个异步值；呈现层只负责把异步值画成载入／错误重试／空态。
5. **传输只有一条。** 登录校验、协议客户端、封面下载共用同一条 HTTP 传输，因此它也是唯一的测试替身注入点（两个适配器：生产传输与测试假传输）。封面组件里走 Flutter 自带 HTTP 栈的那条路径不并入。
6. **不选「薄会话」。** 只把客户端包成非空、取数仍按实体各自成层，会让这一层的接口宽度接近实现（七个成员里四个是纯转发，删除测试判定为浅），且「全库已取回」这件事仍然没有归属 —— 将来改增量加载时本地搜索会静默返回不完整结果。

## 后果

- 七处判空、十条页面守卫、一处播放门闩、一处登出弹栈、一处「未登录→协议异常」全部消失。
- 页面测试不再需要假装未登录；测试默认仍跨**传输**这道既有接缝（真会话 + 假传输），只有当用例意图与取数无关时才替换取数 provider。
- 「全库已取回」这条不变量第一次有地方声明与验证；ADR-0005 那条退化退路（将来改增量加载）终于有了可承接的接缝。
- 播放层与会话解耦后只剩两个真实依赖（两个地址函数）。
- **不改变**取数策略本身（仍是一次取全库）与队列持久化格式；分页、解析与容错规则原样搬进会话内部。
- 页面数据的**失效时机**是独立的行为决策，另行处理；本决策只保证它现在有一个可以失效的落点。
